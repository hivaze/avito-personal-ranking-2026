HOW THE STORED COLUMNS ARE BUILT (code read):
  it_hist_{all,et1..4}_luo (src/features_luo.py): occurrences of the item in the histories of ALL snapshots of train + val + test, minus snapshots of the same non-zero
     user with a later timestamp. Not causal: a holdout row also counts the dense train snapshots AFTER its own time. Test row: dense snapshots end at CUT, i.e. L days
     before the row; afterwards only the 1/37-density val / test snapshots.
  seq_cv_{invd20,pop,norm} (feats_v2/seq_/feat_covis.py): co-visitation in de-duplicated user sequences (latest train feed per user before the cutoff day; all user-0 feeds);
     train row of day d: train days < d; val / test row: all train + val / test histories with ts < own ts; sequences of the same non-zero user are skipped.
  xp_imp_c50 (nn_x/abl/pop1/build_xp_imp_c50.py) = log1p(min(tte_it_imp, 50)); tte_it_imp = the item's impressions in train candidate rows; train row of day d: days < d;
     val / test row: all train days. -> the pop1kd members DO have one recency-dependent input.
  Everything else in the 34 / 27 xt inputs (ctx_nd_*, ctx_hn_*, ctx_hs_*, pre2_*) uses the own feed and own history only: stays as stored.
  Columns that depend on the lag: W8 members = 3 seq_cv + 5 it_hist (8 columns; in-model rank / z of seq_cv_invd20 and it_hist_all_luo follow); pop1kd members = xp_imp_c50.

KNOWN ARTEFACT TO AVOID (COVERAGE_MAP 220 / DATA_PIPELINE_1113 5.3, "T4"): a plain as-of rule "counts up to T - 7 d" leaves 63.6% of holdout feeds with an empty source,
  because the dense data start on Sep 6 (a row of Sep 6 + k with lag L has k - L dense days; test rows have 12). Depth and lag must be separated.

CONSTRUCTION ("exposure-matched lag"), per holdout feed f and candidate row (item j):
  L_f      = lag in days drawn by a hash of feed_id (label-free) from the test distribution of the view: view pub = {6, 7} with the public feed counts as weights,
             view priv = {7, 8, 9} with the private feed counts as weights.
  c_f      = 00:00 MSK of day(t_f) - L_f days (the feed's lagged dense cutoff; t_f - c_f has the same law as t - CUT on test rows of that lag).
  t_post   = t_f - age(f4) (listing creation time, data/feats/life_f4_age_knots.npy, as feat_new/hz_common.py); capped f4 -> old.
  E        = c_f - t_post = the listing's age at the cutoff (on a test row: CUT - t_post).
  D (dense cutoff day of the row) = day boundary nearest to  min(CUT, max(c_f, Sep 6 + clip(E, 0, 14 d))).
     Meaning: the row keeps min(E, 14 d) days of DENSE exposure (what a test row has), taken as the earliest available days.
       listing created inside the dense data (t_post >= Sep 6) or younger than the cutoff: D = c_f = the plain "counts up to T - lag" rule (empty if c_f <= Sep 6);
       E >= 14 d: D = Sep 20 = the full dense window, i.e. the stored value for it_hist (old listings are NOT made stale: the dense window surrounds the row);
       listing created before Sep 6 with 0 < E < 14 d: the first E days of the data instead of the first E days of its life (window shifted later in the item's life).
  A (sparse anchor day) = max(day(c_f), D); sparse days = A + PAT. Sparse snapshots = train feeds of the shared 1/37 hash sample (feat_new/hz_common.sparse_flag) on a
     sparse day, or any val / test snapshot on a sparse day. A sparse day before Sep 6 or on a day without data is lost (no substitution).
  it_hist_*  = occurrences in train snapshots with day < D  +  occurrences in sparse snapshots (day >= D)  +  the own snapshot if not yet counted;
               snapshots of the same non-zero user with a later timestamp are removed everywhere (stored LUO rule); user 0 as stored.
  seq_cv_*   = the stored kernel on: dense part = source_fidx(D) (latest train feed per non-zero user with day < D, all user-0 feeds with day < D), then sparse part =
               sparse train feeds with ts < t_f (causal, as val / test histories are for a test row); same-user sequences skipped; scan cap 3000 as stored.
               Known limit, written now: for D > c_f the history-neighbour side is fresher than on a test row (neighbour listings created after c_f are visible).
  xp_imp_c50 = log1p(min(n, 50)), n = train candidate rows of the item with day < D, minus the own feed's row, minus rows of later feeds of the same non-zero user.
  No label is read anywhere in the construction. Same-user later snapshots are never used.
  Code checks before use: with L = 0 semantics (D = own day for seq_cv / xp_imp; all snapshots for it_hist) the same code must reproduce the stored columns on the holdout rows.

GATE (label-free; decides whether any labelled read of a lagged view is made). Populations: lagged holdout rows of the view vs test candidate rows of the matching part
  (public / private) from feeds with M >= 50; lag-0 (stored) holdout rows for contrast. Age buckets from f4: <1d, 1-3d, 3-7d, 7-10d, 10-24d, 24-76d, >76d (incl. capped).
  Per column and bucket: zero share and mean of the model-scale value (attach_xt transform: log1p for counts; xp_imp_c50 as is). SD = SD of the model-scale column on the test part.
  dZ = holdout-row-weighted mean over buckets of |zero share(holdout view) - zero share(test part)|;  dM = the same for |mean difference| / SD.
  PASS (per view) iff ALL of:
   G1  dZ <= 0.05 for each family primary: it_hist_all_luo, seq_cv_pop, xp_imp_c50;
   G2  no bucket holding >= 5% of the holdout rows has |zero-share difference| > 0.10, for the three primaries;
   G3  dM <= 0.20 for the three primaries;
   G4  dZ of it_hist_all_luo at the lagged view <= 1/3 of its lag-0 value (the view removes at least two thirds of the coverage gap);
   G5  secondary columns (it_hist_et1..4_luo, seq_cv_invd20, seq_cv_norm): dZ <= 0.10 and dM <= 0.30 each.
  Written in advance: the stored table nn_x/w5/hzcd/preflight.txt already shows that OLD listings (> 24 d, 53% of holdout rows) are warmer on stored holdout rows than on
  private rows (zero share 0.144-0.149 vs 0.192-0.200, mean log1p +0.3) and the construction does not change them; this irreducible part (about 0.025 of dZ, 0.10 of dM)
  is inside the thresholds on purpose and is reported as a limit.
  FAIL of the private-like view -> stop: no labelled read of any lagged view; report gate table + control. The public-like view is read only if it passes on its own.
