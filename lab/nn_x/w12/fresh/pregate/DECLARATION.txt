A. DEFINITIONS (fixed)
A1 Universe U = all val + test feeds (43,018). Query row = candidate (item i) of feed f, user u, timestamp t.
   A source feed g counts for the row iff g != f, g shows item i, and user(g) != u.
   user_id 0: every uid-0 feed is treated as its own user (it counts for every other feed, and other uid-0 feeds count for
   it). Variant NZSRC ("without them"): uid-0 feeds are never sources (queries of uid-0 feeds are still scored).
   Same non-zero user: ALL of that user's feeds in U (earlier and later, val and test) are excluded.
A2 Windows:  a   = ts(g) <  t                      (AS-OF, strictly earlier 128 s tick)
             a24 = t - 86400 <= ts(g) < t          (AS-OF, last 24 h; an as-of form, belongs to group A)
             b   = same Moscow day, day = (ts + 10800) // 86400, any time of that day
             c   = |ts(g) - t| <= 86400            (symmetric +-1 day, rolling)
             d   = every feed of U                 (whole val + test period)
             e   = ts(g) >  t                      (later-only; DIAGNOSTIC for step 6, never part of group A)
A3 Forms per window w with count n_w: raw n_w; l_w = log1p(n_w); r_w = within-feed percent rank of n_w (average ties,
   0.5 if all tied); z_w = within-feed z of l_w (0 if the feed sd is 0); i_w = 1[n_w >= 1];
   cs_w = cold * i_w  ("cold in train but shown elsewhere in val / test"), cold = 1[tte_it_imp == 0] (= xp_imp_c50 == 0).
A4 Pool score b = zf(0.5 * zf(preds/ens_FD16P20kd_ft_val.npy) + 0.5 * zf(preds/ens_FD16P20kd_to_val.npy)), zf = within-feed
   z (src/stack_val.feed_rank_z[:, 1]) = the final FD16P20 val score of nn_x/w12/kd/build_r4.py (fin()). Sanity: its plain
   val NDCG is printed and compared with the build_r4 read-out of FD16P20 before anything else.
A5 Splits of test: public-like / private-like by src/pmix.py BOUND. Feed cold share bins = pmix bins (<15, 15-30, 30-45, >=45 %).

B. STEP 1 (coverage) and STEP 2 (descriptive AUC): NO pass / fail criterion. Nothing in sections C-F is chosen from them:
   the model, columns, arms and the rule below are fixed HERE. Step 2 uses val labels in sample and is a sanity read only.
   Within-feed AUC = mean over feeds (that have >= 1 positive and >= 1 negative in the scored subset) of the per-feed AUC
   with ties = 0.5; "among cold" = the same restricted to the cold candidates of each feed. Yardstick: xp_imp_c50.

C. STEP 3 NESTED RESIDUAL READ (the decision)
C1 PRIMARY family (decides): per-feed conditional logit = listwise softmax with multiple positives,
     s = beta * b + sum_j w_j x_j ;  loss = sum over training feeds with >= 1 positive of [ -sum_pos s + npos * logsumexp_feed(s) ]
     + 0.5 * LAMBDA * sum_j w_j^2,  LAMBDA = 10 (beta not penalised); every x_j is divided by its sd over all val rows
     (label-free scaling); L-BFGS-B, start beta = 1, w = 0, maxiter 300.
   CONTROL columns: b ; b*lm ; cold ; cold*b ; cold*lm      with lm = ln(M) - mean over val rows of ln(M).
   ARM = CONTROL + for every window w of the arm these 8 columns:
     min(n_w, 50) ; l_w ; r_w - 0.5 ; z_w ; i_w ; cs_w ; l_w*cold ; l_w*lm.
   Arms:  A   = windows {a, a24}          (AS-OF forms only; THE DECISION ARM)
          B   = windows {b, c, d}         (forms that use later feeds)
          ALL = windows {a, a24, b, c, d}
          L   = window  {e}               (later-only, diagnostic)
   The same four arms are repeated with NZSRC counts (information: "without user 0 as a source").
C2 Folds: 5 folds over val feeds grouped by user_id (every uid-0 feed is its own group, as nn_x/w5/finetune.py
   --u0_singleton), users shuffled with fold seeds 0, 1, 2 (3 x 5 fits per arm). Each fold: fit on 4 folds, score the 5th.
C3 Numbers: per-feed NDCG by src/metrics.ndcg_per_feed (all 14,423 feeds; feeds without positives = 1 in both arms).
   d_f = mean over the 3 fold seeds of [NDCG_f(arm) - NDCG_f(control)]; GAIN = mean_f d_f; SE = sd_f(d_f) / sqrt(14,423)
   (paired per-feed SE); z = GAIN / SE. Plain (unweighted) val is the decision number. Reported next to it, not deciding:
   pmix public / private (src/pmix.weights, wmean_se), feed cold-share bin, day (20718 / 20720), M < 50 / >= 50,
   uid-0 feeds vs others, third of the day (position in the period), per fold seed.
C4 SECONDARY family (information only, never decides): LightGBM lambdarank, init_score = beta_fold * b (beta_fold = the
   coefficient of a conditional logit on [b] alone fitted on the training folds), final score = init + trees;
   num_leaves 15, learning_rate 0.05, 200 rounds (fixed, no early stopping), min_data_in_leaf 100, lambda_l2 10,
   lambdarank_truncation_level 100, feature_fraction 1.0, deterministic, num_threads 12, same folds / seeds.
   Control features [b, M, cold]; arm features = control + [n_w, r_w, z_w, cs_w] per window; arms A and ALL.
   If the secondary clears the bar where the primary does not, this is reported as a disagreement, NOT as PROMISING.

D. STEP 4 PLACEBO
D1 Decision placebo P1 ("profile swap", implements the task's stated intent "destroys the item link, keeps the count
   distribution"): within strata = (Moscow day of the feed) x (cold flag) x (3-hour block of the feed time), the vector of raw
   counts (n_a, n_a24, n_b, n_c, n_d, n_e) is permuted across candidate rows (one permutation per draw, the same for every
   window); l / r / z / i / cs are then recomputed inside each feed. Every row keeps a count vector that really occurs for a
   candidate of the same day, cold status and time of day, but it belongs to a random other item.
   20 draws (>= 10 required), draw seeds 100..119; each draw runs the identical nested read (same folds, 3 fold seeds) for
   arms A, B, ALL. "Above every placebo draw" = GAIN_real(arm) > max over the 20 draws of GAIN_placebo(arm).
D2 Literal placebo P2 (information): the item-id column of the SOURCE rows is permuted across source rows within each Moscow
   day and the counts are recomputed against the true item of each query row. Declared reason why P2 cannot be the decision
   placebo (arithmetic, before running it): a within-day permutation of the item column preserves the day's multiset of
   item ids, so the number of source rows carrying item i on day D stays n_i(D); the query's same-day and whole-period
   counts are therefore still a function of its TRUE item's multiplicity (n_i instead of n_i - 1: the own occurrence is
   relocated instead of excluded) -> the item link is NOT destroyed for windows b, c, d and only the within-day timing is
   randomised for window a. P2 is run with 10 draws (seeds 200..209) and reported as "timing / location placebo".
D3 Reported: the 20 (10) placebo gains per arm, their mean / sd / max, the rank of the real gain, and
   (GAIN_real - mean_placebo) / sd_placebo.

E. DECISION RULE (given by the task; operationalised with C3 / D1; primary family only)
   PROMISING iff arm A (as-of forms alone): GAIN >= +0.0005 AND z >= 2 AND GAIN > every P1 placebo draw of arm A.
   WEAK      iff not PROMISING and (arm B or arm ALL): GAIN >= +0.0005 AND z >= 2 AND GAIN > every P1 draw of that arm.
   NO        otherwise.
   Information flags (do not change the verdict): pmix-private GAIN < -1 SE; NZSRC arm disagreeing in sign with the main
   arm; the secondary family; arm L. Multiple looks are disclosed: 4 arms x 2 source variants x 2 families are read,
   exactly ONE cell (primary family, arm A, uid-0 feeds as sources) decides PROMISING, two cells (B, ALL) decide WEAK.
