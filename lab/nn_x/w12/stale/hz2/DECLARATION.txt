DEFINITION OF THE TRAIN-ROW COUNTERPART ("hz2", causal replay of the test observation process at the row's own calendar position)
  Per feed f (ALL 3,151,208 train feeds, the 30,000 holdout feeds included: their rows give a causal lagged holdout through save_holdout_hz):
    part_f  = public-like with probability 8,562 / 28,595, else private-like   (hash of feed_id, label-free)
    L_f     = lag in days drawn inside the part from the test feed counts above (public {6, 7}, private {7, 8, 9}; the poplag hash and cdf, so a
              private-like holdout feed has the lag poplag's private-like view gave it, a public-like one the lag of poplag's public-like view)
    d_f     = MSK day of the feed;  c_f = d_f - L_f (the feed's lagged dense cutoff, a day boundary).
    sparse days of the feed S_f = (c_f + {2, 4, 6, 7, 8, 9}) restricted to days with data that are <= d_f. The own day (offset L_f) is always one of them.
    sparse snapshots = train feeds of the shared 1/37 hash sample (feat_new/hz_common.sparse_flag) on a sparse day.
  Per candidate row (item j): p = MSK day of the listing's creation time t_f - age(f4) (data/feats/life_f4_age_knots.npy; capped f4 = old).
    T    = {c_f + o : o in {-14..-6, -3, -2, -1}, c_f + o >= p}   = the dense days on which a test row of this lag and listing age can see the listing; X_test = |T|.
    A    = T restricted to days >= Sep 6 (every such day is a dense train day because c_f <= Sep 13).
    EXACT rows (A = T; includes X_test = 0, i.e. listings created on or after the cutoff): dense window W = A, factor r = 1.
          This is the plain rule "dense counts up to T - lag, with the Sep 15-16 hole replayed"; it needs no calibration and no listing age.
    TRUNCATED rows (A smaller than T: the listing was alive before Sep 6, where no data exist; the test-like value is not observable):
          c_r = min(d_f, max(c_f, Sep 6 + m days))            (m = minimum dense depth kept when the calendar allows it; ONE calibrated parameter)
          W   = the earliest min(X_test, n) dense train days in [Sep 6, c_r), n = number of dense train days there (the hole days c_f-5, c_f-4 are NOT
                removed for truncated rows: depth is scarce); r = min(X_test / |W|, 4) (depth correction of the first moment; 0 days -> no dense part).
          Days of W on or after c_f are "fill" days (causal but fresher than the lag); a sparse day that is in W is not counted twice.
  NOTHING IS COUNTED AFTER THE ROW'S OWN DAY, in any column; no dense snapshot of the own day is counted (W ends before d_f).
  The nine inputs:
    it_hist_{all,et1..et4} = r * (occurrences of j in the histories of the train snapshots of the days in W)
                             + occurrences in the sparse snapshots of the days S_f not in W + occurrences in the row's own snapshot (if not yet counted)
                             - occurrences in counted snapshots of the SAME non-zero user with a later timestamp (stored LUO rule; only same-day sparse ones can exist).
    seq_cv_{invd20,pop}    = the stored kernel (feats_v2/seq_/feat_covis.py) over: dense members = for each non-zero user the latest train feed among the days W
                             (every user-0 feed of those days), sparse members = sparse snapshots of the days S_f not in W with ts < own ts; sequences of the same
                             non-zero user skipped; most recent 3000 member occurrences; value = r * dense part + sparse part; pop capped at 3000;
                             seq_cv_norm = invd20 / sqrt(pop + 1) from the combined values.
    xp_imp_c50             = log1p(min(r * (train impressions of j on the days W), 50))   (test rows count train impressions only: no sparse part).
  OWN USER: the stored rule of each column is kept, because the val check below requires the same code to reproduce the stored val columns: it_hist counts the
    row's own snapshot and EARLIER snapshots of the user (a test row has them), never a later one; seq_cv skips every sequence of the user; xp_imp counts earlier
    impressions only. The task text says "nothing from the row's own user": I read it as "nothing that can carry the row's label = no later snapshot / own-day
    impression of the user", which holds; dropping the own snapshot would make train rows differ from test rows. Stated in the report.
  NOT CAUSALLY BUILDABLE (stated now): the dense data start on Sep 6, the lag is 6-9 d and the test depth is 12 d, so a row needs 18-23 d of past for an exact
    replay of an old listing; the train data span 14 d. For truncated rows hz2 is an approximation whose quality falls with the feed's day (Sep 6: no past at all).
    Gate numbers are therefore also given by day group (Sep 6-8, Sep 9-12, Sep 13-14, Sep 17-19).
