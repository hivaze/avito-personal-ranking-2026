3. IMPORTANT: --fsw "mean 1 over the feeds of each batch" is close to a no-op here -> recommend fsw25t / fsw50t
=====================================================================================================================
SplitData.batches cuts every batch inside one M bucket of width 16 (Mpad = ceil(M/16)*16). Every batch is therefore nearly
M-homogeneous, and a per-batch normalisation only re-weights feeds inside a bucket.
Computed over all 3,151,208 train feeds (the smoke batches above agree):
  - per-batch normalised weight sd: 0.049 (ALPHA 0.25) / 0.097 (ALPHA 0.5);
  - loss-weight share of M>=50 feeds: 0.4904 unweighted -> 0.4906 / 0.4908 per-batch normalised, vs 0.606 / 0.709 with
    --fsw_norm train (one constant = mean M^ALPHA over the run's training feeds, so the epoch-mean weight is 1).
The smoke agrees: fsw25 / fsw50 end at loss 2.6568 / 2.6570, vs 2.6567 for ref.
Only the train-normalised version does what the background asks ("weight feeds by size; large feeds carry most of the loss").
fsw25 / fsw50 are implemented and in lane.sh exactly as specified, but I recommend running fsw25t / fsw50t instead
(fill_jobs_T1117_fswt.txt). That saves ~32 GPU-hours on a predictable null.
If the lead wants the literal arms anyway, fill_jobs_T1117.txt is the spec's file.

5. RISKS / NOTES
=====================================================================================================================
- Optimiser scale: AdamW and Muon are nearly invariant to a global loss scale, so the arms act through the RATIO of the two parts.
    wcl05 / wcl10 = the within-category part at 1.5x / 2x the category part.
    ccl05 = the category part at 1.5x.
    wcl = ccl = LAMBDA would be (almost) a no-op.
  This is the intended lever, but the size of the shift is set by that ratio.
- Under KD the target t contains the teacher softmax. wcl therefore also up-weights the TEACHER's within-category order, and
  ccl the teacher's category mass, not only the clicks.
- The new terms use CUDA index_add / scatter_reduce, whose float summation order is not deterministic. Arm runs are not bitwise
  reproducible run to run. Production training is already non-deterministic, and the flag-off path is unchanged (G1).
- No clipping occurs in any arm (max p90 0.36 < 1.0), so clipping does not mask the extra gradient.
- The new arms are refused together with --rdrop_cd / --sam_cd (they recompute the main loss) and with --loss_norm idcg.
  Neither is used by K / L.
- The older nn_x/w5/tests AST proofs (test_w5.py / test_w7.py chain) already predate the 11-14 KD flags and were stale before this
  change. My own default-off proof is in this folder (T4 + G1).
- train.py / lane.sh were swapped by rename. Any process that had them open keeps the old version; none was running at the time.
- Stopping fill.sh leaves claim dirs only for started jobs. A failed job leaves logs/queue/failed_<v> and is not retried
  automatically.
