======================================================================================================================================
question      "Does co-training the full ranker on lists built from history events extract more than the pre2 input channel already does from
              the same targets? This is the only route that turns GPU-hours into training examples."
construction  "Pseudo-feeds built on the GPU from the batch's own histories. Target: a new type-1/source-1 event at t <= 63. History: the events
              older than t + g, g ~ U[16, 64], recency re-indexed. Negatives: the source feed's non-clicked candidates. user_emb zeroed (a learned
              no-user vector); a fourth domain embedding; f1-f5 and the 34 pre-computed columns on their missing path; K9 weight 0; listwise CE
              weight 0.3; plateau only. The cooldown stays on real feeds for an absolute 19,670 steps (never cooldown_frac x total). Holdout users
              and later same-user snapshots are never a source. The pseudo domain gets its own context-free linear head on [content, category],
              so the shared pathway is not paid to learn the past-click marginal (shortcut AUC 0.590 is not removed by logQ). Report a
              set-attention-masked variant on pseudo rows as information (set leak 0.608 vs 0.582)."
first test    "10-epoch 2-seed pair at pseudo:real 1:1 against w5_e10_base s951/952, @last primary, E rule + diversity clause. Information arm:
              pseudo + xdrop_pre2 vs abl_e10_xdrop_pre2 (from ENCODER-DOSE (B)), to test substitution. No 2-epoch GO: gains shrank from 2 to 10
              epochs in every recorded case."
kill          "member Δval < +0.001, OR holdout < 0, OR the gain appears only without pre2"
escalation    "4:1 dose read (12-14 GPU-h), then a 7-root family with FT (60-70 GPU-h). A width arm only if the pseudo d128 member beats real-only
              by >= +0.0037 val (one effective doubling) AND WIDTH-GATE is GO. In that case one d192 pseudo pair (20-26 GPU-h) must reach
              d192 − d128 >= +0.0015 val, holdout >= +1 SE and an in-pool replay >= +0.0005."

CONSTRUCTION AS IMPLEMENTED (cd_arms11.py docstring is the reference; per plateau step, from the gathered real batch of B feeds; history newest-first):
  draws      P = ceil(R B) (source row, t, g) draws; the source rows are a cyclic random permutation of the batch rows (at an integer R every row is a
             source exactly R times); g ~ U{16..64} per draw; a dedicated torch.Generator (seed + 1100011), so the real path's RNG is untouched.
  source     rows of HOLDOUT USERS are never sources (user ids of the 30K holdout feeds; user 0 = the pooled bucket, never matched; the mask is logged).
             "Later same-user snapshots" (val / test rows) are not read by this train-only stage at all (they matter for an FT variant only).
  target     t uniform over the eligible indices t in [0, 63]: a valid event with an embedding, event_type 1 from event_source 1, NEW (its item occurs in
             no older event of the loaded history, index > t; items identified by the item-table row, verified one-to-one with item_id over 22.1M items,
             0 exceptions), NOT A CANDIDATE of the source feed (none of the feed's M candidates, clicked or not, is that item), and t + g <= H_cap − 1.
             => by construction the positive of a pseudo-feed is never a candidate of its source feed (the set-centroid leak named by the reviewers).
  history    the source row's events at index >= t + g, re-indexed to 0.. (the newest kept event is exactly g positions older than the target; the
             target and the whole gap are dropped); H' = H_cap − t − g >= 1.
  negatives  the source feed's NON-CLICKED candidates (y == 0) in their original order, MINUS the candidates whose item occurs in the history at an index
             < t + g (the user did interact with them after the pseudo request time: masked out, not used as negatives); a draw with no remaining
             negative is dropped. Exactly one positive per pseudo-feed (slot 0 = the target item's embedding + category).
  inputs     f1-f5 = 0 and all 34 --xt columns = 0 (has:pre2_fe = 0) on EVERY candidate of a pseudo-feed; user_emb = 0 (cos_u = dot_u = 0; the user
             token is u_lin's bias = the learned no-user vector); user0 flag of the source row; domain one-hot ROW 2; no production positions
             (use_pos=False; the recipe has --no_pos anyway).
  head       --pseudo_head 1: logit += Linear(128->1)(normalised content embedding) + Embedding(54,1)[category] on pseudo rows only; zero-init (an exact
             no-op at step 0, unit-tested); parameters OUTSIDE the model's state_dict (own AdamW no-decay group, the run's lr schedule, not inside
             clip_grad_norm_); saved to ckpt/<v>_pseudo_head.pt. Every checkpoint therefore stays loadable by finetune.py / holdout_eval.py /
             stale_pred.py (no cfg change; the smoke's checkpoint cfg keys == w5_e10_base_s951's).
  loss       loss = loss_real (listwise + K9 aux, unchanged) + 0.3 x listwise_loss(pseudo logits, norm=--loss_norm feed, denom=--max_feeds 512):
             the SAME normalisation and constant denominator as the real loss (one pseudo-feed weighs 0.3 of one real feed). fw None (the recipe's
             --prand_base -1). K9 aux never on pseudo rows. CLIPLOG main := main + 0.3 loss_p (aux stays K9 only).
  steps      an EXTRA forward/backward inside the same step: step count 98,350, t_cool 78,680 and the cooldown's 19,670 steps are unchanged (unit-
             and smoke-tested: same 'total steps'); pseudo-feeds on steps < t_cool only; cooldown / pool batches never see them.
  variant    --pseudo_noset 1: the candidate-set self-attention blocks are skipped on pseudo rows only (model.use_set toggled around the pseudo forward).
DEVIATIONS / INTERPRETATIONS of the spec text (for the lead's review; each is a one-line change if rejected):
  (i)   "the events older than t + g": implemented as index >= t + g (the newest kept event is g positions older than the target), not > t + g.
  (ii)  "f1-f5 and the 34 pre-computed columns on their missing path": applied to EVERY candidate of a pseudo-feed, not to the target only — the
        target has no such inputs (they exist for candidate rows only) and a target-only missing pattern would identify the positive (a shortcut far
        above the 0.59 content shortcut). The within-feed z / rank of these columns are then constant on pseudo rows.
  (iii) "a fourth domain embedding": the pseudo rows use row 2 of the EXISTING 3-row domain table (the "exploration" row that the recipe never trains,
        tr.dom[:, 2] = 0, nor uses at inference, infer_domain 1) — a dedicated embedding without a model / checkpoint change. The lead's brief said
        "the exploration/random-like value": row 2 ("exploration") was chosen over row 1 ("random-like") so that pseudo rows do not share the
        inference-time token.
  (iv)  "Negatives: the source feed's non-clicked candidates": minus the candidates the user interacted with at an index < t + g (label noise).
  (v)   "new": within the loaded history window (<= --max_hist 256 events); items beyond the window are invisible to the model as well.
  (vi)  the head sits outside the model (checkpoint compatibility), its gradients are not part of the global clip (3 tensors, 183 parameters).
  (vii) "pseudo:real 1:1" = one draw per real feed in the batch (R = 1); draws without an eligible target / negative are dropped, so the realised
        pseudo count per batch is below B (statistics below). "listwise CE weight 0.3" = --pseudo_w 0.3 on top of R = 1.
