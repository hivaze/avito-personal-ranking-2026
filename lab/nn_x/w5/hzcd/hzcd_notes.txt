WHAT THE FLAG DOES (--hzcd, default off)
  From the cooldown start (step t_cool = round((1 - cooldown_frac) * total); step 0 in the CD harness, --cooldown_frac 1.0
  right after --init) every TRAINING batch, regular and pool, is gathered through cd_arms6.HzTrainView: the ordinary
  SplitData.gather of the train split, then the 5 LUO popularity columns of b['xt'] are overwritten by the horizon-limited
  counts of data/feats_new/train/it_hist_hz_{all,et1,et2,et3,et4}.npy. Columns (from the model's xt_names, so --init runs
  are covered; preset cvnd_pre2s = 34 inputs): 3 it_hist_all_luo -> it_hist_hz_all, 4 it_hist_et1_luo -> it_hist_hz_et1,
  5 et2, 6 et3, 7 et4. Column 3 is also an xt_rel column, so its in-model within-feed pct-rank and z (model.dense_features)
  are computed from the hz values in those batches.
  Scaling (identical to the luo path): data.SplitData.attach_xt transforms names starting with it_hist as log1p(max(x, 0)),
  NaN -> 0, stores float16, and gather returns xt[ci].float(). cd_arms6.xt_transform reproduces attach_xt's branches (tested
  bitwise against MiniSplit.xt built by the same rules) and load_hz casts with torch .to(device, float16) as attach_xt does.
  Downstream the hz values pass through exactly what the luo values pass through: xt_drop (0 in F7), the xt_rel rank / z,
  and the dense normalisation f_mean / f_std (fitted on luo batches at model build, or loaded from the --init checkpoint).
  The hz counts live on the same log1p-count scale, so sharing the normalisation is the intended parity (val/test luo
  values go through the same constants).
  Untouched: feature_stats at model build, the selection holdout (eval_subset reads tr), val / test predict, save_last,
  save_holdout and holdout_eval.py (all read tr / va / te). Extra output with --hzcd: preds/holdout/nn_<v>_holdout_hz.npy =
  the selected checkpoint's holdout preds scored THROUGH the hz view (same numerics as the as-built holdout file: predict
  without TF32); the as-built nn_<v>_holdout.npy is written as before. Holdout feeds have hz lag 0 (feat_new/hz_common.py),
  so the two files differ only through same-day listings. Not combinable with --hcap (asserted). GPU cost: +2.3 GB (the
  5 hz columns, fp16, 246.7M rows) and a few small copy kernels per training batch; the view is released before the test
  split loads.
