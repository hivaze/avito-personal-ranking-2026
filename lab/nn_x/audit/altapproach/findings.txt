"nested" = z(G3) + w z(x), w in {0,.05,.1,.2,.3,.5} chosen on 4/5 of the feeds (GroupKFold by user, user-0 singletons),

(M x cold-share) mix (src/pmix.py). "cell" = INSIGHTS_1112 item-5 cell: warm positive (LUO>0) with a same-category
history event at hpos<8 whose category is G3's top (LSE) category, vs the warm same-category negatives G3 ranks above it
(62,016 pairs, 2.6% of all pos-neg pairs; G3 has AUC 0 there by construction).

1. What the pre2s pretraining corpus actually was (asked explicitly)
=====================================================================================================================
pretrain/build_corpus.py + pretrain_report.md section 1-2:
  * sequences: train = LATEST train snapshot per non-zero user + every user-0 train feed; val/test = EARLIEST snapshot
    per non-zero user over val U test + every user-0 feed. 2.59M sequences, 463.6M events, old->new. So the corpus already
    contains the val and test histories (unsupervised test-period adaptation), oversampled x4 (--vt_rep) in v3/v4.
  * val-side features come from twins trained WITHOUT test snapshots (--exclude_test 1) to keep the information horizon
    symmetric; test-side from train+val+test. Same-user later snapshots are never in any corpus (leak audit flat).
  * model: SASRec/ARGUS-style causal transformer d=384, 4 layers, 8M dense + 40M-row item-ID table (dim 64/128), targets
    = next NEW feed-originated open (et1/es1) + next new item, sampled softmax with logQ, 2 epochs (22 min / GPU).
  * use in the ranker: 9 scalar features (pre2_fe/new, z, hmax32/8, fe_noid, id_contrib, idmax32) as train-stage inputs
    (cvnd_pre2s: +0.0019 at 3 ep, +0.0009 at 10 ep) and FT extras. The encoder weights were never used as an
    initialisation of the ranker's history encoder, and the ID table never entered the ranker (nn/train.py --init loads
    ranker checkpoints only; grep finds no seqenc import outside pretrain/).
What is transductive today: it_hist_*_luo (counts all snapshots of all splits, minus same-user-later; 1.9% of val count
mass from later other-user snapshots, 0.9% test); seq_cv_* for val/test rows use train sources + val/test snapshots with
ts < own ts (causal inside the split); pre2 test features see all test snapshots; ALS/item2vec on disk (als_*) were
trained on train+val+test histories (clean version). My probe shows the fully transductive versions add nothing.

4. Weak spots / eye fatigue noticed
=====================================================================================================================
* Decisions keep being made on val (14.4K feeds, paired SE 0.0005-0.001) with many looks; the holdout is train-period and
  over-rewards popularity inputs 2.5x (LEAKAGE-1). Both yardsticks are known-biased in opposite directions; the pmix
  column is the only private-shaped one and is report-only. Fine for vetoes, weak for picking between +0.0003 candidates.
* Pool rho 0.93 (n_eff ~1.07): more members of any recipe are worthless; every gain must come from a different mean
  function. The only generational mean-function change available is TRUNC (and maybe R3).
* The private-mix weights put 2x weight on user-0 and H<10 feeds, where the FT half helps and the TO half is weaker;
  if a future pool drops FT members (item 2(c) of INSIGHTS: FT only ~4 members), re-check the user-0 / H<10 slices.
* The public leaderboard cannot resolve anything below ~0.003; the #1 entry should not change the plan.
