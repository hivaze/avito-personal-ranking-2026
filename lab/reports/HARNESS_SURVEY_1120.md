Source file of the tables in `docs/13-how-the-work-was-run.md`. Three search agents found 33 systems. ## evolutionary-search

### EvoRank
- organisation as claimed by the finder (check the corrections): University of Maryland and an independent researcher
- first public (finder): 2026-08; date on the page: 30 Aug 2026
- open source: yes
- source: https://arxiv.org/abs/2609.22196 (abstract); also read https://arxiv.org/html/2609.22196v1 (full text) and https://github.com/shabazpatel/evorank (Apache-2.0)
- What the page says: Open LLM-guided evolutionary loop, built on SkyDiscover's AdaEvolve search controller, that discovers full learning-to-rank pipelines (features, models, losses, ensembles) on Expedia ICDM 2013 data, then re-scores winners on 60k held-out queries in a transfer audit.
- Result on the page: Three runs each converged within 50 iterations (about ten dollars each); held-out NDCG@10 on 59,902 queries 0.4316, 0.4322, 0.4352 vs 0.4296 for Optuna-tuned LambdaMART. Kaggle late submission of the full-scale pipeline: 0.5196 private NDCG@38, 20th of 340 (top 6 percent) (arXiv, 30 Aug 2026).
- Relevance note (finder, judgement): Closest match: ranking task, noisy fitness. Its first campaign's gains were 'almost entirely fitness noise' (fold noise 0.007-0.009 NDCG); it proposes a pre-search 'headroom gate'.
- Corrections made by the checker: The claim holds, with these precision points. (1) The abstract page has no NDCG numbers, SkyDiscover/AdaEvolve, or affiliations. These come from the arXiv HTML full text: AdaEvolve is named in Sec. 3.1, the Table 1 values are 0.4316 / 0.4322 / 0.4352 vs 0.4296, and the affiliations are University of Maryland, College Park and Independent Researcher. (2) "About ten dollars" is per run (the paper says "at 50 iterations and ten dollars each"). (3) The top-6% placement is not from the 0.4316-0.4352 numbers. Those are pipelines trained on the small fitness fold. The placement comes from a separate one-shot Kaggle late submission of the full-scale pipeline (0.5196 private NDCG@38, 20th of 340). The tuned baseline scored 0.5140 (30th), and the 2013 winners' hand-built ensembles stay ahead (0.5398). The page says this submission benefits from hindsight because the winners' lessons were in the seeded knowledge. (4) Only the best run (s2) beats the baseline on all three objectives, and revenue is within noise. (5) The paper was accepted at the GenAIECommerce'26 workshop at RecSys 2026 and the repo is Apache-2.0.

### Evolutionary Ensemble Search (EES)
- organisation as claimed by the finder (check the corrections): Impulse AI
- first public (finder): 2026-09; date on the page: Submitted on 11 Sep 2026 (v1, Fri, 11 Sep 2026 19:18:06 UTC)
- open source: unknown
- source: https://arxiv.org/abs/2609.17590
- What the page says: A role-specialized council turns task evidence into search directions; an evolutionary engine makes children by code mutation, structured pipeline edits and crossover. Each child gets its own validation evidence; compatible predictions compete in a validation-gated ensemble. Lessons are retrieved across runs.
- Result on the page: A public MLE-bench Lite development ledger records medal-threshold artifacts on 19 of 22 tasks (86.36%), with best outcomes of 11 gold, five silver, and three bronze. The authors call it an achieved development result, not a blind autonomous-agent success rate. The campaign included grade feedback between runs.
- Relevance note (finder, judgement): Design fits competition work (population, ensembling, validation gate), but no code link seen and the headline number is not a clean autonomous score.
- Corrections made by the checker: Core description and numbers match the abstract. Differences: (1) The page never mentions "Impulse AI". It lists only the authors Juan P. Madrigal-Cianci and Eshan Chordia, with no affiliation on the abstract page, so the attribution is unverified. (2) The abstract says "role-specialized council" plus an orchestrator and execution specialists, not "agents". (3) It adds a 86.36% figure and says the campaign also used external-source routes and mixed confirmation procedures, besides grade feedback between runs. (4) The page says the ledger is public, but it shows no code or repository link, and the paper is CC BY 4.0, so open-source status stays unknown. Only the abstract page was read, not the full PDF or HTML.

(2) The 79% figure is not in the abstract. It comes from the HTML full text (https://arxiv.org/html/2611.22828v1, Section 6 and Appendix G), in the part of the page I could only read as a model-extracted summary, not verbatim. (3) That probe is described as a diagnostic, not a selection rule, and uses CatBoost CV scores. (4) Open source stays unknown. Appendix K says an anonymized code archive accompanies the submission. ### SkyDiscover (AdaEvolve, EvoX)
- organisation as claimed by the finder (check the corrections): UC Berkeley Sky Lab
- first public (finder): 2026-02; date on the page: 2026-02 (repo news: open-sourced); Berkeley project page posted March 3, 2026; latest repo news 2026/09
- open source: yes
- source: https://github.com/skydiscover-ai/skydiscover (also read https://sky.cs.berkeley.edu/project/skydiscover/ and https://github.com/skydiscover-ai/skydiscover/blob/main/skydiscover/optimize/README.md)
- What the page says: Open-source UC Berkeley framework: Optimize evolves programs against your scoring function via a loop of solution selector, context builder, generator and evaluator, with AdaEvolve (multi-island, UCB, migration) and EvoX; one uv run skydiscover optimize command. Also has Synthesize.
- Result on the page: ~34% higher median score than OpenEvolve, GEPA, and ShinkaEvolve on Frontier-CS (172 problems) under the same budget (repo README). Project page (posted March 3, 2026) says median scores improved by ~34% over the same three. No ML-training result is reported.
- Relevance note (finder, judgement): It is the engine EvoRank used for ranking pipelines. Apache-2.0. Benchmark claims are the project's own.
- Corrections made by the checker: Mostly supported. (1) The main README does not mention the four-part loop. The Optimize README (same repo) does, as a diagram: solution selector, context builder, solution generator, evaluator. It describes five steps: sample, prompt, generate, evaluate, add. The evaluator is the user's own script. (2) The Optimize README describes AdaEvolve as "Multi-island adaptive search with UCB, migration, and paradigm breakthroughs". UCB is a bandit method, but the page never says "bandit allocation". The main README describes AdaEvolve as adaptive search that tunes its own settings as it runs. EvoX is "Self-evolving paradigm that co-adapts solution generation and experience management" (main README: "AI that optimizes its own optimization process"). (3) One command is confirmed: uv run skydiscover optimize evaluator.py --search adaevolve --model gpt-5 -i 100. An initial program is optional. (4) "Same budget" appears in the repo README, not on the Berkeley project page, which gives only ~34% over the three baselines on 172 Frontier-CS problems. (5) Dates: the repo news says "[2026/02] ... open-sourced SkyDiscover", which matches the claim. The README also lists a Sept 2026 SkyDiscover-Synthesize release (builds end-to-end systems), a separate product beyond the claim. (6) License is Apache-2.0. The 766 stars and 111 forks are from the page as fetched.
