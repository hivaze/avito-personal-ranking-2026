### 1.2 The channel: a feed-level fact can only act through a candidate attribute

NDCG is computed per feed. Adding any function of the feed (hour, weekday, weather, FX, payday, outage, election) to every candidate's score leaves the order unchanged. External information enters only as an interaction with something that differs between candidates: category x time (demand curves), listing age or posting time x calendar, popularity x day, price x payday (no price field exists; f2/f3/f5 are not prices). Since the categories are anonymised, the demand curve of every category was derived from the data (train positives by category x day / weekday / hour, exploration and production separately; val by day; test exposure by day) and tested nested on G3. **If the data-derived curve adds nothing, an external series for the same category can only add noise on top of it.** This is the feature-design principle for the whole branch, and it is what the user's "per-day / per-week / per-hour market stats" become once the categories are coded: a category x calendar prior.
